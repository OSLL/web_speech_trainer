## Запуск проекта

При первом запуске (после клонирования) нужно указать конфиг через
`.env` — он не коммитится и по умолчанию не создаётся:

```bash
echo "APP_CONF=app_conf/config.ini" > .env
docker compose up -d
```

Конфигурация берётся из `app_conf/config.ini`.

## Тестовый режим

Чтобы вместо обычного конфига подключить тестовый (с тестовым
пользователем), укажите в `.env` другой путь:

```bash
echo "APP_CONF=app_conf/testing.ini" > .env
```

`app_conf/testing.ini` — такой же конфиг, но с секцией `[testing]`
(данные тестового пользователя/задачи) и настройками тестовой БД.
Без некоторых ключей в нём (`[redis]`, часть `[constants]`, нужных
для генерации вопросов) приложение не запускается или падает при
обработке загруженного файла — поэтому эти ключи были добавлены
в `testing.ini` в этом PR.

Чтобы попасть в тестовый режим:

1. Создать `.env` с `APP_CONF=app_conf/testing.ini` (см. выше).
2. Поднять сервисы **с профилем** `interview_profile` — без него
   `redis` и `celery_worker` (нужны для фоновой генерации вопросов
   по загруженному ВКР) не запускаются:
```bash
   docker compose --profile interview_profile up -d --build --force-recreate
```
   > `--build` обязателен после любых правок в `app_conf/` — эти файлы
   > копируются в образ при сборке (`COPY . .` в Dockerfile), а не
   > монтируются как volume, поэтому без пересборки контейнер продолжит
   > использовать старый конфиг.
3. Открыть `http://<host>:5000/init/` — маршрут активен только при
   `[testing] active=True` в выбранном конфиге, он создаёт тестовую
   сессию и тестовую задачу в БД, эмулируя LTI-запуск от LMS вручную.
4. Открыть `http://<host>:5000/` — попадёте в тренажёр с уже
   созданной тестовой попыткой, без реальной LMS.

## Кратко про профили

С профилем по умолчанию (`docker compose up -d`, только `web`+`db`)
тестовое окно `/init/` откроется нормально — оно не зависит от Redis.
Но как только вы загрузите ВКР и запросите генерацию вопросов, запрос
упадёт с ошибкой подключения к Redis: без `redis`/`celery_worker`
(поднимаются только с `--profile interview_profile`) некому принять
и обработать задачу генерации.

С профилем `interview_profile` дополнительно поднимаются:
- `redis` — брокер очереди для Celery;
- `celery_worker` — воркер, выполняющий фоновую генерацию вопросов
  по загруженному ВКР (`tasks.generate_questions`);
- `whisper` — сервис распознавания речи.

## ПРОШЛОЕ (не работает)

### Сборка
- `docker-compose up init-llm` - загружается модель, устанавливаются зависимости для LLM-модуля

### Использование
- `docker-compose up llm` - поднимаем контейнер с LLM-модулем
- `docker-compose up app` - поднимаем контейнер с основным приложением
- `docker compose exec app python run.py /app/static/vkr_examples/VKR1.docx --no-overflow-logs` - запускаем генерацию вопросов по файлу ВКР
